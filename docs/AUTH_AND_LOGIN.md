# نظام الدخول في مِعاف — التشخيص والحل

> آخر تحديث: 2026-10-09 · ينطبق على الإصدار الحالي في هذا المستودع (React + Express + TypeScript)

---

## 1. المشكلة كما وردت

> «النظام يطلب كلمة سر لا أعرفها، ولا أستطيع الدخول.»

## 2. التشخيص الفعلي (مُثبت بالتشغيل لا بالتخمين)

المشكلة **ليست** أن كلمة السر مفقودة، ولا أن حساب المدير غير موجود.
كلمة السر التأسيسية موجودة ومعلنة في الكود (`admin` / `Admin@123456`) وتنجح فعلاً.
المشكلة أن النظام **يقفل نفسه فور نجاح الدخول**. التسلسل الحقيقي:

| # | الخطوة | النتيجة المقاسة |
|---|--------|-----------------|
| 1 | `POST /api/auth/login` بـ `admin` / `Admin@123456` | **HTTP 200** — الدخول ينجح |
| 2 | نفس الاستجابة تحمل `mustChangePassword: true` | لأن `requiresPasswordChange()` تعتبر كلمة السر التأسيسية «معلنة للجميع» |
| 3 | `GET /api/patients` بالرمز نفسه | **HTTP 403** `PASSWORD_CHANGE_REQUIRED` |
| 4 | `GET /api/reports/dashboard` | **HTTP 403** نفسه |
| 5 | الواجهة تفتح `ChangePasswordModal` بخاصية `forced` | **بلا زر إغلاق ولا إلغاء** |
| 6 | زر «استعادة بيانات الخادم التأسيسية» في شاشة الدخول | **HTTP 401** — لأنه يستدعي `/api/backup/reset` المحمي بمصادقة |

### لماذا يصبح القفل دائماً

النافذة الإجبارية تطلب **كلمة المرور الحالية**. وهي معروفة فقط ما دامت كلمة السر التأسيسية
قائمة. لكنها تصبح مجهولة في أي من هذه الحالات الواقعية:

- غيّر أحدهم كلمة المرور سابقاً ولم يسجلها → `passwordHash` لم يعد يطابق أي كلمة معروفة.
- أُنشئ مستخدم عبر `POST /api/users` → يولّد `generateTemporaryPassword()` كلمة عشوائية
  تُطبع **مرة واحدة** في الاستجابة، وتضيع إن لم تُحفظ.
- نُفّذ `POST /api/users/:id/reset-password` → نفس الشيء.
- دخلت 5 محاولات خاطئة → `lockedUntil` يقفل الحساب 15 دقيقة فوق كل ذلك.

عندها لا يبقى أي مخرج: لا دخول، لا تجاوز للنافذة، لا إعادة ضبط، ولا أداة استعادة.

**الخلاصة:** التصميم كان يفترض أن كلمة السر التأسيسية معروفة دائماً، وكل مسار يخالف هذا
الافتراض ينتهي بقفل لا يمكن فتحه من داخل النظام.

## 3. الحل المنفَّذ

### 3.1 وضعان للمصادقة بدل وضع واحد مفروض

يُحدَّد الوضع من `meaaf.config.json` أو متغير البيئة `MEAAF_AUTH_MODE`:

| الوضع | السلوك | متى يُستخدم |
|-------|--------|-------------|
| `open` **(الافتراضي الآن)** | دخول تلقائي كمدير النظام. لا شاشة دخول، لا كلمة مرور، لا نافذة إجبارية | تشغيل محلي على جهاز واحد، وهو المطلوب حالياً |
| `password` | شاشة دخول + BCrypt + صلاحيات أدوار + سياسة تغيير كلمة السر | عند نشر متعدد المستخدمين لاحقاً |

```bash
npm run start:open        # الوضع المفتوح
npm run start:password    # وضع كلمات المرور
```

> `scripts/serve.ts` موجود لأن صيغة `MEAAF_AUTH_MODE=open tsx server.ts` لا تعمل على
> Windows (cmd/PowerShell). هذا الملف يضبط المتغير داخل العملية نفسها، فيعمل الأمر
> على Windows وLinux وmacOS بنفس الشكل.

### 3.2 ما تغيّر في الخادم

**`server/config.ts`** (جديد) — مصدر واحد للحقيقة: `AUTH_MODE`، `DEFAULT_TENANT_ID`،
`OPEN_ADMIN_USERNAME`، `APP_VERSION`. أي قيمة غير معروفة تسقط إلى `open` مع تحذير مطبوع،
حتى لا يؤدي خطأ إملائي إلى قفل الجميع.

**`server/auth.ts`**
- `requiresPasswordChange()` تُرجع `false` دائماً في الوضع المفتوح → **نهاية القفل الإجباري**.
- `ensureAdminUser()` — يجد المدير أو **ينشئه** إن لم يوجد (تثبيت جديد، نسخة مستعادة،
  أو ملف بيانات حُذف/عطّل فيه كل المديرين). يصلح تلقائياً: `isActive`، `isDeleted`،
  `lockedUntil`، `failedLoginAttempts`، `mustChangePassword`، ومرجع الدور.
  الحساب المُنشأ يأخذ **تجزئة عشوائية 32 بايت** لا تُطبع ولا تُخزَّن نصاً صريحاً،
  فلا يمكن تجاوز الوضع المفتوح لاحقاً بتخمين كلمة سر.
- `getOpenSessionToken()` — جلسة واحدة مشتركة تُعاد استخدامها بدل جلسة لكل طلب
  (كان سيؤدي إلى تضخّم `sessions` بلا حد).
- `authenticate()` — في الوضع المفتوح، الرمز المفقود/المنتهي/التالف **لا يُرجع 401**؛
  يُوقَّع الطلب تلقائياً ك مدير، ويُرسل الرمز الصالح في رأس `X-MEAAF-Session`.
  هذا يلغي فئة كاملة من الأعطال: إعادة تشغيل الخادم كانت تمحو الجلسات (في الذاكرة)
  فتُخرج المستخدم بلا سبب.

**`server/api.ts`**
- `GET /api/auth/mode` (عام) — يخبر الواجهة هل تحتاج شاشة دخول أصلاً.
- `POST /api/auth/auto-login` (عام في الوضع المفتوح) — يعيد رمز جلسة + المستخدم +
  المنشأة + 32 صلاحية، ويسجّل حدث `AutoLogin` أو `AutoProvision` في سجل التدقيق.
- `POST /api/auth/login` — في الوضع المفتوح يعيد جلسة صالحة مع `notice` يوضح أن بيانات
  الدخول المرسلة تم تجاهلها، بدل رسالة «كلمة مرور خاطئة» المضللة.
- `POST /api/backup/reset` — يستدعي `resetOpenSession()` بعد إعادة البذر، حتى لا تشير
  الجلسة المشتركة إلى مستخدم حُذف.

### 3.3 ما تغيّر في الواجهة

- **`src/App.tsx`** — إقلاع من ثلاث خطوات: جلسة موجودة؟ → ما الوضع؟ → دخول تلقائي أو
  شاشة دخول. النافذة الإجبارية تُفتح فقط عندما `authMode === 'password'`.
- **`src/views/ServerUnreachable.tsx`** (جديد) — عند تعذّر الوصول للخادم تظهر رسالة الخطأ
  الحقيقية مع خطوات التشغيل، **لا** شاشة دخول يستحيل أن تنجح.
- **`src/components/Header.tsx`** — شارة توضح الوضع، وإخفاء زرّي «كلمة المرور» و«خروج»
  في الوضع المفتوح (لا معنى لهما، وخروج كان يعني حلقة دخول فوري).
- **`src/components/StatusBar.tsx`** (جديد) — شريط حالة بأسلوب تطبيقات سطح المكتب،
  وكل قيمة فيه حقيقية: فحص اتصال فعلي كل 10 ثوانٍ على `/api/auth/mode`، مؤشرات من
  `/api/reports/dashboard` كل 60 ثانية، الوضع، المستخدم، الدور، المنشأة، الساعة، الإصدار.
- **`src/services/api.ts`** — `getAuthMode()`، `autoLogin()`، وتبنّي تلقائي للرمز المُجدَّد
  من رأس `X-MEAAF-Session`.

### 3.4 أداة استعادة الدخول (مخرج دائم)

`scripts/unlock-admin.ts` — تعمل على ملف البيانات مباشرة، حتى لو كان الخادم لا يقلع:

```bash
npm run unlock-admin -- --list                              # كل الحسابات وحالتها
npm run unlock-admin -- --open                              # فحص جاهزية الدخول التلقائي
npm run unlock-admin                                        # فك قفل admin + كلمة مرور مؤقتة
npm run unlock-admin -- --user dr.khalid                    # حساب محدد
npm run unlock-admin -- --password "كلمة-جديدة-12-حرفا"     # كلمة مرور تختارها
```

تزيل أسباب القفل الأربعة معاً: القفل المؤقت، التعطيل/الحذف، علامة «يجب تغيير كلمة المرور»،
وكلمة المرور المجهولة. الكلمة الجديدة تُطبع مرة واحدة فقط.

## 4. أدلة التحقق المقاسة

### الوضع المفتوح

| الفحص | قبل | بعد |
|-------|-----|-----|
| `POST /api/auth/auto-login` بلا أي بيانات | غير موجود | **200** + رمز + 32 صلاحية |
| `GET /api/patients` بعد دخول بكلمة السر التأسيسية | **403** `PASSWORD_CHANGE_REQUIRED` | **200** (مريضان) |
| `GET /api/reports/dashboard` | **403** | **200** `{patients:2, revenue:150, debit:172.5, credit:172.5}` |
| `GET /api/patients` بلا رمز إطلاقاً | **401** | **200** |
| `GET /api/patients` برمز تالف (بعد إعادة تشغيل) | **401** | **200** + رأس `X-MEAAF-Session` |
| `POST /api/backup/reset` من شاشة الدخول | **401** (زر ميت) | **403** برسالة سبب صريحة (الحماية من عملية مدمّرة باقية) |
| 6 محاولات بكلمة سر خاطئة | قفل الحساب 15 دقيقة | لا قفل — `failedLoginAttempts=0`، `lockedUntil=null` |
| قاعدة بيانات **بلا أي مدير** | لا دخول ممكن | `created: true` → مدير جديد بـ32 صلاحية، وتجزئته لا تطابق `Admin@123456` |
| كل نقاط `GET` (19 نقطة) | — | **200** في الوضع المفتوح |

### وضع كلمة المرور (اختبار انحدار — لم يُكسر شيء)

| الفحص | النتيجة |
|-------|---------|
| `GET /api/auth/mode` | `{mode:"password", requiresPassword:true}` |
| `POST /api/auth/auto-login` | **403** `AUTO_LOGIN_DISABLED` |
| `GET /api/patients` بلا رمز | **401** كما كان |
| دخول صحيح | **200** + `mustChangePassword: true` |
| دخول خاطئ | **401** + `failedLoginAttempts: 1` |
| `POST /api/auth/change-password` | **200** «تم تغيير كلمة المرور بنجاح» |
| الدخول بالكلمة الجديدة | **200** + `mustChangePassword: false` + قراءة المرضى **200** |
| `unlock-admin` على حساب مقفل حتى 2030 | أُزيل القفل والعلامة، وحُدِّثت كلمة المرور |

## 5. تحذير أمان صريح

الوضع المفتوح يعني: **أي شخص يصل إلى المنفذ 3000 يملك صلاحيات المدير كاملة** — بما فيها
الفواتير والقيود المحاسبية والنسخ الاحتياطي وسجل التدقيق وإدارة المستخدمين.

لذلك:

- ✅ مناسب: جهاز واحد في عيادة، أو شبكة داخلية مغلقة، أو بيئة تطوير.
- ❌ غير مناسب: أي نشر على الإنترنت، أو جهاز مشترك، أو بيئة فيها بيانات مرضى حقيقية
  تخضع لمتطلبات خصوصية.
- الخادم يستمع على `0.0.0.0:3000` (مقصود لأجل المعاينة والشبكة المحلية). قبل أي نشر
  فعلي: بدّل إلى `password`، واضبط `MEAAF_INITIAL_ADMIN_PASSWORD` خارج المستودع،
  وقيّد الاستماع، وضعه خلف HTTPS.
- الجلسات في الذاكرة: إعادة تشغيل الخادم تُنهيها. في الوضع المفتوح يُعاد الدخول تلقائياً؛
  في وضع كلمة المرور يلزم دخول جديد (سلوك مقصود).

العودة إلى الحماية الكاملة سطر واحد في `meaaf.config.json`:

```json
{ "authMode": "password" }
```

ثم `npm run unlock-admin -- --password "..."` لضبط كلمة مرور المدير قبل أول دخول.
