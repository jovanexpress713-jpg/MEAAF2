## 0. تصحيح جوهري: ما هو المشروع فعلاً

`README.md` السابق و`docs/PRODUCTION_AUDIT.md` و`docs/WINDOWS_INSTALL.md` و
`docs/available_package_README.md` تصف مشروعاً **.NET 8 / WPF / SQL Server** بمجلدات
`MEAAF.Core` و`MEAAF.UI` و`installer/` وسير عمل GitHub Actions.

**لا وجود لأي من ذلك في هذا المستودع:**

```
$ find . -name "*.cs" -o -name "*.csproj" -o -name "*.sln" -o -name "*.xaml" -o -name "*.ps1"
(لا نتائج)
```

لا `installer/`، لا `.github/workflows/`، لا `scripts/verify_structure.py`، لا `src/MEAAF.sln`،
لا `Run_Professional_Build.bat`، ولا `MEAAF_FULL_COMPLETE.zip`.

**المشروع الحقيقي** هو تطبيق ويب كامل المكدس بلغة واحدة (TypeScript):

| الطبقة | التقنية الفعلية |
|--------|-----------------|
| الواجهة | React 18.3 + Vite 6 + Tailwind CSS v4 + lucide-react |
| الخادم | Node.js + Express 5 (ملف واحد `server.ts` + 10 وحدات في `server/`) |
| التخزين | ملف JSON واحد `data/meaaf_enterprise_db.json` عبر `server/db.ts` |
| المصادقة | bcryptjs + جلسات في الذاكرة (بلا JWT، بلا قاعدة جلسات دائمة) |
| الاختبارات | `server/tests/run_tests.ts` (17 اختباراً) |
| الحجم | ~10,925 سطراً · 18 شاشة · 53 نقطة API |
| ملفات `db/*.sql` | مخطط SQL Server **خط أساس توثيقي غير مستخدم** — الكود لا يقرأه |

هذا الفارق ليس تفصيلاً: أي خطة مبنية على README القديم (بناء WPF، تشغيل SQL Server،
Inno Setup) ستفشل فوراً. عُدّل `README.md` ليطابق الواقع، وبقيت الملفات القديمة مع
تحذير صريح في أولها.

## 2. ما لا يعمل / غير مكتمل (بصراحة)

### 2.1 عوائق بنيوية

| البند | الواقع |
|-------|--------|
| **تخزين JSON** | كل الحفظ كتابة ملف كامل. لا معاملات حقيقية، لا تقافل، لا فهارس. `beginTransaction/rollback` نسخ عميق في الذاكرة — يفقد أي تحديث متزامن بين البدء والتراجع. **غير صالح لأكثر من مستخدم واحد فعلي** |
| **الجلسات في الذاكرة** | إعادة تشغيل الخادم تمحوها. مقبول في الوضع المفتوح (دخول تلقائي فوري)، وغير مقبول في وضع كلمة المرور الإنتاجي |
| **بلا HTTPS** | `server.ts` يستمع `0.0.0.0:3000` نصاً صريحاً. مع الوضع المفتوح = صلاحيات مدير كاملة لكل من يصل للمنفذ |
| **`db/*.sql` غير مستخدم** | 5 ملفات مخطط SQL Server لا يقرأها أي كود. إمّا أن تُعتمد كوجهة ترحيل حقيقية أو تُنقل إلى `docs/` كتصميم |
| **تطبيق مكتبي حقيقي** | لا يوجد. هو تطبيق ويب. لا Tauri ولا Electron ولا WPF ولا مثبّت Windows |

### 2.2 ميزات ناقصة

| الميزة | الحالة |
|--------|--------|
| المواعيد والاستقبال | ❌ غير موجودة إطلاقاً (لا جدول، لا شاشة) |
| العيادات والزيارات | ❌ غير موجودة (يوجد `offices` و`departments` كهيكل تنظيمي فقط، بلا زيارة أو كشف) |
| الملف الطبي السريري | ❌ لا تشخيص، لا وصفات، لا تحاليل، لا تاريخ مرضي |
| الطباعة | ❌ لا معاينة، لا قوالب، لا تصدير PDF، لا طابعات حرارية |
| الصيدلية (صرف/تشغيلة/صلاحية) | ❌ يوجد مخزون أصناف فقط، بلا صرف ولا تتبع تشغيلة |
| المختبر والأشعة | ❌ غير موجودة |
| التنويم | ❌ غير موجود |
| المشتريات والموردون | ❌ غير موجودة |
| الموارد البشرية | ❌ غير موجودة |
| الإقفال المالي السنوي | ⚠️ فترات تُفتح/تُقفل، بلا قائمة إقفال ولا أرصدة افتتاحية |
| المرتجعات والمدفوعات | ✅ موجودة في الخادم (`/payments`, `/refunds`, `/cancel`) |
| الفروع والمزامنة بين الأجهزة | ⚠️ `sync/push` يقبل عمليات بلا آلية حل تعارض موثوقة |
| العمل دون إنترنت | ⚠️ `OfflineStore` طابور محلي أولي، بلا مزامنة ثنائية |
| الرخصة | ⚠️ جدول + توقيع محلي، بلا شاشة تفعيل ولا ربط بقرار الدخول |
| إعادة الضبط التأسيسي | ⚠️ تحتاج `MEAAF_ALLOW_FACTORY_RESET=true` — الزر في `BackupView` يعرض رسالة السبب (ليس زراً ميتاً، لكنه معطل افتراضاً) |

### 2.3 ملاحظات على جودة الشاشة

- `LoginView` ما زال يعرض «بيانات الاعتماد التأسيسية» نصاً صريحاً داخل بطاقة الدخول.
  في الوضع المفتوح الشاشة لا تظهر أصلاً، لكن يجب حذف هذا الصندوق قبل أي نشر بوضع كلمة المرور.
- الخط العربي: `index.css` يطلب `Tajawal` من Google Fonts عبر `index.html`. **يعمل فقط
  مع إنترنت**. للتشغيل المكتبي المستقل يلزم تضمين ملفات الخط محلياً.
- `src/views/AccountingAdmin.tsx` و`InvoiceActionDialog.tsx` موجودان لكن `App.tsx` لا
  يوجّه إليهما مباشرة (يُستخدمان داخل شاشات أخرى) — تأكد قبل اعتبار أي منهما «شاشة مكتملة».
- بيانات البذر تحمل تواريخ `2026-01-xx` ثابتة، فمؤشرات «اليوم» في التقارير قد تبدو فارغة
  على بيانات تجريبية. ليست علة، لكنها تربك العرض.

### المرحلة 2 — القرار البنيوي (**يتطلب قراراً منك قبل أي كود**)
التخزين JSON لن يحمل نظاماً صحياً/محاسبياً حقيقياً. الخيارات:

| الخيار | الجهد | النتيجة |
|--------|-------|---------|
| أ) **Tauri + React الحالي + SQLite** | متوسط | تطبيق Windows حقيقي خفيف (~10MB)، نفس الواجهة، معاملات وفهارس حقيقية، عمل بلا إنترنت |
| ب) **Electron + React الحالي + SQLite** | متوسط | أسهل من Tauri، أثقل (~150MB)، نفس الفوائد |
| ج) البقاء ويباً + **PostgreSQL** | أقل | متعدد المستخدمين فعلياً، لكنه يبقى متصفحاً ولا يعمل بلا خادم |
| د) .NET 8 + WPF (ما يصفه README القديم) | **إعادة بناء كاملة** | التخلص من ~11 ألف سطر موجودة تعمل |

التوصية: **(أ)** — يحفظ كل الشاشات الـ18 الموجودة، ويحقق «مكتبي مستقل على Windows»
بأقل تعقيد، وSQLite يلبّي قواعدك (لا رصيد سالب، قيود متوازنة، soft delete، تدقيق)
بقيود ومعاملات حقيقية.

### المرحلة 3 — الإصدار 1.0 الوظيفي (حسب أولوياتك)
1. المواعيد والاستقبال (جداول + شاشة + ربط بالمريض)
