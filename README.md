## 3. الدخول: تلقائي وبدون كلمة مرور

**لا توجد شاشة دخول ولا كلمة مرور في الإعداد الافتراضي.** عند تشغيل الخادم يدخل
المستخدم مباشرة كمدير النظام، ويُنشأ حساب المدير تلقائياً إن لم يوجد.

```bash
npm install
npm run start:open      # أو npm run dev — الوضع المفتوح هو الافتراضي
# افتح http://localhost:3000
```

كيف يعمل:

1. الواجهة تستدعي `GET /api/auth/mode` فتعرف أن الوضع `open`.
2. تستدعي `POST /api/auth/auto-login` **بلا أي بيانات** فتستلم رمز جلسة بـ32 صلاحية.
3. `ensureAdminUser()` في الخادم يجد المدير أو ينشئه، ويصلح أي حالة قفل موروثة
   (معطل / محذوف / مقفل / مطالب بتغيير كلمة مرور).
4. أي طلب برمز منتهٍ أو تالف (مثلاً بعد إعادة تشغيل الخادم) يُوقَّع تلقائياً بدل `401`.

### سبب هذا التغيير

النسخة السابقة كانت **تقفل نفسها فور نجاح الدخول**: الدخول بـ`admin` / `Admin@123456`
ينجح (`200`) لكنه يعيد `mustChangePassword: true`، فترد كل الشاشات بـ`403
PASSWORD_CHANGE_REQUIRED` وتفتح نافذة تغيير كلمة مرور **بلا زر إغلاق**، تطلب كلمة
السر الحالية. وإذا كانت كلمة السر قد تغيّرت سابقاً (أو أُنشئ مستخدم بكلمة مؤقتة تُطبع
مرة واحدة) يصبح القفل دائماً: لا دخول، لا تجاوز، ولا إعادة ضبط — لأن زر الاستعادة في
شاشة الدخول كان هو نفسه محمياً بمصادقة (`401`).

التشخيص الكامل بالأدلة المقاسة والحل خطوة بخطوة في
**[`docs/AUTH_AND_LOGIN.md`](docs/AUTH_AND_LOGIN.md)**.

### إعادة تفعيل كلمات المرور لاحقاً

```jsonc
// meaaf.config.json
{ "authMode": "password" }
```

أو `npm run start:password`، أو `MEAAF_AUTH_MODE=password`. يعود عندها كل السلوك
الأصلي: شاشة دخول، BCrypt، صلاحيات أدوار، قفل بعد 5 محاولات، وسياسة 12 حرفاً —
وقد اختُبر ذلك انحدارياً نقطة بنقطة.

> ⚠️ **تحذير أمان:** الوضع المفتوح يمنح صلاحيات المدير كاملة (فواتير، قيود، نسخ
> احتياطي، إدارة مستخدمين) لأي طرف يصل إلى المنفذ 3000. مناسب لجهاز واحد أو شبكة
> داخلية مغلقة، **وغير مناسب إطلاقاً لأي نشر على الإنترنت أو لبيانات مرضى حقيقية**.

### نسيت كلمة المرور / الحساب مقفل؟

```bash
npm run unlock-admin -- --list      # كل الحسابات وحالتها
npm run unlock-admin                # فك قفل admin + كلمة مرور مؤقتة تُطبع مرة واحدة
npm run unlock-admin -- --user dr.khalid --password "كلمة-جديدة-12-حرفا"
npm run unlock-admin -- --open      # فحص جاهزية الدخول التلقائي
```

تعمل الأداة على ملف البيانات مباشرة، حتى لو كان الخادم لا يقلع.

## 5. ما يعمل

- **الدخول التلقائي** كمدير النظام، وإنشاء/إصلاح حساب المدير تلقائياً، واستعادته من سطر الأوامر.
- **عزل متعدد المنشآت**: كل استعلام مقيّد بـ`tenantId`، وكل دور مرتبط بمنشأته. مُختبر.
- **المرضى**: بحث وإنشاء ملف مريض برقم طبي وهاتف وتاريخ ميلاد.
- **الفوترة**: إصدار فاتورة بضريبة 15% مع **قيد محاسبي مسودة من 3 أسطر** (ذمم مدينة /
  إيرادات / ضريبة مستحقة) في عملية واحدة، ومدفوعات ومرتجعات وإلغاء بأسباب.
- **المحاسبة**: قيود مزدوجة كمسودات، واعتماد بعد التحقق من التوازن، و**رفض القيد غير
  المتوازن** برسالة عربية واضحة، ودليل حسابات (8 حسابات/منشأة)، وفترات تُفتح وتُقفل،
  وميزان مراجعة يستبعد غير المعتمد.
- **المخزون**: أصناف بتكلفة وسعر كأعداد صحيحة (سنتات) لدقة كاملة، وحركات توريد،
  و**رفض الكمية السالبة**.
- **الإدارة**: مستخدمون وأدوار بكتالوج 32 إذناً، إعادة تعيين كلمة مرور، فك قفل،
  محطات عمل، تذاكر دعم، سجل تدقيق لكل حدث حساس.
- **الترحيل**: اكتشاف المصدر، staging محدود، ربط الأعمدة، تحقق من الحقول والتكرار،
  استيراد ذري مع تدقيق (10,000 صف / 25 MB للدفعة).
- **النسخ الاحتياطي**: تصدير حزمة معزولة للمنشأة.
- **المزامنة**: `sync/pull` بمؤشر تتابعي (`syncSeq`) للأجهزة غير المتصلة.
- **شريط حالة مكتبي**: اتصال حي (فحص كل 10 ثوانٍ)، مؤشرات حقيقية، الوضع، المستخدم،
  الدور، المنشأة، الساعة، الإصدار.

## 6. ما لا يعمل / ناقص

**عوائق بنيوية**
- التخزين ملف JSON يُكتب كاملاً عند كل حفظ: لا معاملات حقيقية، لا تقافل، لا فهارس.
  `beginTransaction/rollback` نسخ عميق في الذاكرة يفقد أي تحديث متزامن بينهما.
- الجلسات في الذاكرة تُمحى بإعادة التشغيل (غير مؤثر في الوضع المفتوح، ومؤثر في وضع كلمة المرور).
- بلا HTTPS، والاستماع على `0.0.0.0` — مع الوضع المفتوح هذا مكشوف بالكامل.
- `db/*.sql` مخطط SQL Server لا يقرأه أي كود.
- **لا يوجد تطبيق مكتبي**: لا Tauri ولا Electron ولا WPF ولا مثبّت Windows.

**وحدات غير موجودة إطلاقاً**
- المواعيد والاستقبال · العيادات والزيارات والكشف · الملف الطبي السريري (تشخيص/وصفة/تحاليل)
- الطباعة (معاينة، قوالب، PDF، طابعات حرارية)
- الصيدلية كصرف (الموجود مخزون أصناف فقط) · المختبر · الأشعة · التنويم
- المشتريات والموردون · الموارد البشرية

**ناقص جزئياً**
- الإقفال المالي: فترات تُفتح/تُقفل بلا قائمة إقفال ولا أرصدة افتتاحية.
- الترحيل: مكتمل للمرضى فقط؛ لا خرائط ولا استيراد للفواتير والمخزون والقيود.
- المزامنة: `push` يقبل عمليات بلا آلية حل تعارض موثوقة؛ `OfflineStore` طابور أولي بلا
  مزامنة ثنائية الاتجاه.
- الرخصة: توقيع وتحقق محليان بلا شاشة تفعيل ولا ربط بقرار الدخول.
- `BackupView → إعادة الضبط` تحتاج `MEAAF_ALLOW_FACTORY_RESET=true` (الزر يعرض السبب
  بوضوح، فهو معطل عمداً لا ميت).
- الفرز في الجداول غير متسق بين الشاشات.
- الخط العربي `Tajawal` يُحمَّل من Google Fonts في `index.html` → **لا يعمل بلا إنترنت**؛
  يلزم تضمينه محلياً لأي تشغيل مستقل.
- `LoginView` ما زال يعرض بيانات الدخول التأسيسية نصاً صريحاً (الشاشة لا تظهر في الوضع
  المفتوح، لكن يجب حذف الصندوق قبل نشر بوضع كلمة المرور).

## 7. الخطوة التالية المقترحة

التخزين JSON لن يحمل نظاماً صحياً/محاسبياً حقيقياً، والهدف المعلن «تطبيق مكتبي مستقل
على Windows». أنسب مسار يحفظ الـ18 شاشة الموجودة:

**Tauri + هذا الواجهة React نفسها + SQLite** — تطبيق Windows حقيقي خفيف، معاملات
وفهارس وقيود حقيقية تلبّي قواعدك (لا رصيد سالب، قيود متوازنة، soft delete، تدقيق)،
وعمل بلا إنترنت، مع إبقاء وضع المصادقة قابلاً للتبديل كما هو الآن.

البدائل ومقارنة الجهد في القسم 3 من [`docs/PROJECT_STATUS.md`](docs/PROJECT_STATUS.md).

## 8. الإعدادات

`meaaf.config.json` (اختياري — القيم الافتراضية تعمل بدونه)، ومتغيرات البيئة تتقدم عليه:

| المفتاح | متغير البيئة | الافتراضي | المعنى |
|---------|--------------|-----------|--------|
| `authMode` | `MEAAF_AUTH_MODE` | `open` | `open` = دخول تلقائي · `password` = شاشة دخول |
| `defaultTenantId` | `MEAAF_DEFAULT_TENANT_ID` | `tenant-001` | منشأة حساب المدير التلقائي |
| `openAdminUsername` | `MEAAF_OPEN_ADMIN_USERNAME` | `admin` | اسم المدير التلقائي |
| `appVersion` | `MEAAF_APP_VERSION` | `1.0.0` | يظهر في شريط الحالة |
| — | `MEAAF_ALLOW_FACTORY_RESET` | غير مضبوط | `true` يسمح بإعادة الضبط التأسيسية (تطوير فقط) |

قيمة `authMode` غير معروفة تسقط إلى `open` مع تحذير مطبوع، حتى لا يؤدي خطأ إملائي إلى
قفل الجميع خارج النظام.

## 9. بيانات الدخول المرجعية (وضع `password` فقط)

في وضع كلمة المرور، حسابات البذر هي `admin` و`dr.khalid` و`admin_tenantB` بكلمة
`Admin@123456`. هذه كلمة معلنة في الكود **وتُستخدم للتطوير فقط**؛ النظام في وضع كلمة
المرور يطالب بتغييرها عند أول دخول. غيِّرها أو استخدم `npm run unlock-admin`.
في الوضع المفتوح لا تُستخدم هذه الكلمة إطلاقاً — حساب المدير المُنشأ تلقائياً يحمل
تجزئة عشوائية 32 بايت لا تُطبع ولا تُخزَّن نصاً صريحاً.
