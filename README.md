# مِعاف | MEAAF
## منظومة إدارة صحية ومحاسبية — نسخة قيد الاستكمال

**حالة الإصدار: غير جاهز للإنتاج.** تمت مراجعة الحزمة وفك ملفات المصدر إلى بنية المشروع، وإصلاح عوائق بناء وأخطاء عزل بيانات وصلاحيات، واستكمال بعض الشاشات والتدفقات. لكن لا يتوفر .NET SDK أو SQL Server في بيئة المراجعة هذه، لذلك لم يُنفّذ بناء C# أو اختبارات تكامل فعلية.

## التقنية والمشاريع

- Windows desktop باستخدام WPF و.NET 8.
- SQL Server لبيانات النظام، وSQLite محلياً كقاعدة أولية لطابور offline.
- `MEAAF.Core` — النماذج والعقود والتحقق.
- `MEAAF.Data` — الوصول إلى SQL Server والمستودعات وSQLite.
- `MEAAF.Security` — تسجيل الدخول، الصلاحيات، التدقيق، والتحقق من توقيع الرخصة.
- `MEAAF.Business` — المرضى، الفوترة، القيود، المخزون، التقارير، النسخ الاحتياطي، وترحيل البيانات.
- `MEAAF.Connectors` — موصل SQL Server لمصدر الترحيل.
- `MEAAF.UI` — واجهة WPF عربية.
- `MEAAF.Tests` — اختبارات قواعد التحقق المحاسبي.

## متطلبات التشغيل

- لتشغيل المثبّت: Windows 10/11 ‏64-bit؛ حزمة Windows self-contained تتضمن .NET 8/WPF Runtime.
- SQL Server 2019 أو أحدث؛ يجب أن يستطيع حساب خدمة SQL Server الكتابة إلى مسار النسخ الاحتياطي.
- شهادة TLS موثوقة لخادم SQL؛ سلسلة الاتصال الافتراضية تستخدم `Encrypt=True` و`TrustServerCertificate=False`.
- للبناء من المصدر: Windows و.NET 8 SDK وInno Setup 6 لإنشاء المثبّت.

## إنشاء مثبّت Windows

على Windows نفّذ `installer/Build-Windows-Installer.ps1`. يشغّل السكربت الاختبارات، وينشر تطبيق WPF self-contained لـ`win-x64`، ثم ينشئ المثبّت عبر Inno Setup 6. الناتج في `artifacts/installer/MEAAF-Setup-0.1.0-win-x64.exe`. يوجد أيضاً سير عمل GitHub Actions في `.github/workflows/windows-installer.yml` لبناء الحزمة ورفعها كأثر غير موقّع. تفاصيل إعداد قاعدة البيانات والاتصال في [دليل Windows](docs/WINDOWS_INSTALL.md). لا ينفّذ المثبّت ملفات SQL ولا يضمّن كلمات مرور. الحزمة غير موقّعة؛ يلزم توقيعها واختبارها قبل التوزيع.

## إعداد قاعدة جديدة

> مخطط SQL Server الحالي خط أساس بديل للتثبيت الجديد، وليس ترقية للمخطط القديم متعدد المنشآت. خذ نسخة احتياطية ولا تطبّقه فوق قاعدة مستخدمة.

1. نفّذ بالترتيب على SQL Server 2019 أو أحدث:
   - `db/001_schema.sql` — إنشاء قاعدة `MEAAF_DB` ومخططات المحاسبة والتنويم والصيدلية والتأمين والتدقيق.
   - `db/002_seed.sql` — إدراج شجرة الحسابات الافتراضية مع حل علاقات الأب بواسطة رمز الحساب.
   - `db/003_indexes.sql` — إنشاء الفهارس وقيود التفرد التشغيلية.
   - `db/004_license.sql` و`db/005_patient_migration.sql` — موضعان محجوزان لا يجريان تغييرات في خط الأساس الحالي.
2. السكربتات تنشئ قاعدة جديدة فقط بصورة آمنة. لا تحذف الجداول القديمة ولا تحوّل بيانات المخطط السابق تلقائياً.
3. للبناء والتشغيل من المصدر على Windows نفّذ:

   ```powershell
   dotnet restore src/MEAAF.sln
   dotnet build src/MEAAF.sln -c Release --no-restore
   dotnet test src/MEAAF.sln -c Release --no-build
   dotnet run --project src/MEAAF.UI/MEAAF.UI.csproj
   ```

   أو استخدم `Run_Professional_Build.bat`. هذه أوامر تطوير؛ لا يحتاج المستخدم النهائي إلى SDK عند تثبيت الحزمة self-contained.

> `scripts/verify_structure.py` يتحقق من وجود الملفات، ومسارات الحل، وسلامة XML وبعض روابط الواجهة فقط؛ **لا يحل محل** `dotnet build` أو اختبار SQL Server.

## إعداد مفتاح توقيع الرخصة

إذا استُخدم مكوّن توقيع الرخصة محلياً، اضبط `MEAAF_LICENSE_SECRET` خارج المستودع بمفتاح عشوائي سري لا يقل عن 32 بايتاً. لا يوجد حالياً مسار تفعيل داخل التطبيق، لذا لا يُعد ذلك بديلاً عن خادم إدارة رخص.

## ما يعمل في هذه النسخة

- تسجيل الدخول باستخدام BCrypt والتحقق من حالة المستخدم والمنشأة.
- فحص الصلاحيات في طبقة الأعمال، وربط أدوار المستخدمين بالمنشأة نفسها.
- البحث عن المرضى وإنشاء ملف مريض.
- إصدار فاتورة داخل معاملة واحدة مع قيد محاسبي مسودة وسجل تدقيق.
- إنشاء القيود كمسودات واعتماد القيد بعد التحقق من التوازن.
- إضافة المنتجات وتسجيل الكميات الواردة للمخزون مع سجل تدقيق.
- مؤشرات لوحة التحكم لا تحتسب القيود غير المعتمدة.
- ترحيل المرضى من جدول SQL Server: اكتشاف المصدر، staging محدود، ربط الأعمدة والتحقق من الحقول/التكرار، ثم استيراد ذري مع سجل تدقيق. تُحذف صفوف staging بعد نجاح الاستيراد، ويوجد تنظيف يدوي للخرائط الفاشلة الأقدم من 30 يوماً بصلاحية وتدقيق. الحد 10,000 صف و25 MB للدفعة.
- أوامر نسخ SQL Server الاحتياطي والاستعادة محمية بصلاحيات؛ يجب اختبار الاستعادة على نسخة منفصلة قبل أي استخدام فعلي.

## نواقص معروفة — لا تعتمد على الميزات التالية إنتاجياً

- **الترحيل:** مسار الربط والاستيراد متاح للمرضى فقط. لا توجد خرائط أو تسوية أو استيراد نهائي للفواتير والمخزون والقيود والكيانات الأخرى؛ يلزم اختباره على نسخ قواعد المصدر الفعلية قبل الاعتماد.
- **المزامنة:** لا توجد نقطة اتصال أو آلية حل تعارض؛ لذلك ترفض خدمة المزامنة التنفيذ بدلاً من وسم بيانات بأنها أُرسلت دون إرسالها فعلاً.
- **Offline:** `OfflineStore` نموذج أولي لطابور محلي ولا توجد مزامنة ثنائية الاتجاه أو استعادة تعارضات.
- **الرخصة:** التوقيع والتحقق المحليان متوفران كمكوّن أمني فقط؛ لا توجد شاشة تفعيل أو خدمة إصدار أو ربط فعلي بقرارات الدخول.
- **المحاسبة:** يتضمن خط أساس SQL دليل حسابات هرمي وقيود يومية، لكنه لا يفرض حتى الآن توازن القيد على مستوى قاعدة البيانات ولا يوفّر دورة كاملة للإقفال والمرتجعات والمدفوعات.
- **المستخدمون:** يتوفر تغيير كلمة المرور الحالية، لكن إدارة المستخدمين/الأدوار وإعادة تعيين كلمة المرور ليست مكتملة.
- **الإنتاج:** لم يُختبر التشغيل على Windows أو SQL Server. أُضيف سكربت ومشروع لإنشاء مثبّت Windows self-contained، لكن لم تُبنَ الحزمة فعلياً هنا؛ الاختبارات على Windows والتوقيع الرقمي ما زالت مطلوبة.
- ملفات SQL الحالية خط أساس لتثبيت جديد؛ لا تستخدمها كترقية تلقائية لقاعدة قائمة قبل نسخها ومراجعة مخططها.

**الخلاصة:** هذه نسخة مصدر محسّنة وقابلة للمراجعة، وليست اعتماداً بأن النظام كامل أو آمن للاستخدام السريري/المالي الفعلي.
